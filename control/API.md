# RolyPolyOps control API

[Русский](API.ru.md)

Base path /ops. All requests/responses JSON except HTML/CSS/JS assets. Browser origin exact configured HTTPS origin. Times UTC ISO strings. Shared authentication, enrollment and the operation queue also serve Compose applications. The original demo routes below remain supported. Automatic failover is unavailable.

The [Compose service and storage contract](contracts/compose-v2.md) defines `/api/storages`, `/api/services` and scoped Compose operations, including encrypted credential envelopes and exact-snapshot recovery. See the [Compose guide](../docs/en/compose-services.md) for the owner workflow.

GET /api/session -> {authenticated,setupRequired,version,csrf?,needsPasswordChange?}. Password-only admin login POST /api/login {password}; initial password private recovery kit. POST /api/password {currentPassword,newPassword}, POST /api/logout. Auth cookies HttpOnly/Secure/SameSite Strict; every authenticated mutation X-CSRF-Token. GET session can be unauthenticated; other data requires login.

GET /api/overview -> {version,revision,setup:{completed,profile,backupInterval},nodes:[{id,name,role,lastSeen,connected,status:{supported,version,serviceHealthy,serviceLabel,disk:{total,free},snapshots:[{id,time,size?}],lastBackup?,lastRestore?,schedule:{backup:{enabled,next?},restore:{enabled,next?}},preview?,error?}}],jobs:[{id,nodeId,action,status,createdAt,startedAt?,endedAt?,stage?,snapshotId?,result?,error?}],capabilities:{automaticFailover:false},alerts:[{severity,code,nodeId?}]}.
Node role primary or recovery. A disconnected node is stale after 45s. Node status is observed metadata, never secrets. Job statuses queued,dispatched,running,succeeded,failed,outcome_unknown. Snapshot IDs canonical64 lowerhex. Backup may briefly pause the supported demo writer. Results include actual snapshot and checks, not mere process start.

POST /api/enrollments {name,role} -> {id,code,expiresAt,command}. Code one-use 15min, digest only persisted; command root install from published immutable source, or command using install.py on a supplied checkout when no release URL configured. Display connection step and expiration; no SSH credential form. Owner can connect server by running enrollment command through their existing SSH access. No private keys transported.

POST /api/settings {profile:'single'|'pair_assisted',backupInterval:'15min'|'hourly'|'daily',expectedRevision} -> {revision}. Saving policy is separate from actual host timer change; schedule UI must use set-schedule operation and only say applied after agent result. Profile pair_assisted needs at least 2 nodes; single needs at least1. Cluster and automatic pair unavailable.
POST /api/setup/complete {} -> {completed:true} only when fresh supported primary and recovery exist for pair, successful primary backup job + recovery restore-check of exactly that snapshot, no active or unknown operation. Single may use same node restore check with explicit same-host storage warning. Setup may be rerun from settings.

POST /api/plans {nodeId,action,snapshotId?,parameters?} -> {id,nodeId,action,snapshotId?,expiresAt,revision,summary:{code,pausesService,isolated,retainsCopy},parameters}. Plans bind node/action/snapshot/parameters/revision and expire10min. Node must be connected and package supported. Actions backup,verify,restore-check,restore-preview,remove-preview,set-schedule. Restore actions require exact known snapshot, not latest. schedule parameters {interval:'15min'|'hourly'|'daily'} primary only. remove-preview only existing owned preview. Preview is a new retained isolated copy, never replacing live site.
POST /api/jobs {planId,idempotencyKey} -> {job} HTTP202. Idempotency key UUID; repeat exact request returns same job; conflicting reuse409. Only valid current plan accepted; enqueue once per plan. Serialize service operations globally. GET /api/jobs/{id} -> {job}. No raw shell execution, no delete-repository API.

Agent: POST /agent/enroll {code,hostname,version} -> {nodeId,token,role}. POST /agent/sync Authorization Bearer <per-node-token> {nodeId,instanceId,status,reports:[{id,nonce,status:'running'|'succeeded'|'failed'|'outcome_unknown',stage?,result?,error?}]} -> {job?:{id,nonce,action,snapshotId?,parameters}}. Only matching node+nonce reports accepted. Dispatcher may resend one dispatched job until acknowledged; local durable receipt prevents rerun. A running/unknown job keeps global mutation lock. Controller restart retains jobs/sessions/plans; agent restart never blindly repeats a prior running receipt. Token appears once, digest persisted server side; all config root-only on agent. Agent always uses certificate-validated HTTPS except explicit local test mode. Invalid payload fields rejected; body <=256KiB. Errors {error:'stable_code',message?:friendly}. No tracebacks/secrets returned.

Lifecycle endpoints: POST /api/enrollments/{id}/cancel, POST /api/nodes/{id}/revoke, POST /api/nodes/{id}/enrollment, POST /api/jobs/{id}/cancel (queued only), and POST /api/jobs/{id}/reconcile (inspection without replay). Configuration/enrollment changes increment revision; polling does not. A matching durable running report acknowledges dispatch. Terminal receipts are retained locally after report acknowledgment. Reconciliation resends the same job identity with reconcile:true and may retain outcome_unknown when no exact proof exists.

The host incarnation `instanceId` is a required UUID persisted with its receipt directory. A changed incarnation invalidates old queued assignments and makes in-flight work unknown before any resend. An independent seen index prevents replay when an individual receipt disappears. Reports may carry `inspected:true`; plain duplicate terminal reports do not impersonate an owner-requested inspection.

`overview.orphanReports` contains bounded own-node discrepancies (up to 128 entries per node), with `inspectionRequested`; jobs may expose `reconcileRequested`. `catalog_receipt_orphaned` explains the protection hold. An authenticated heartbeat is not rejected merely because its catalog is older than a receipt. Such results are quarantined rather than adopted as successful jobs. Unknown/quarantined work blocks conflicting mutations.

POST `/api/nodes/{nodeId}/orphans/{jobId}/reconcile` requests inspection, not replay. Agent sync may return `inspectOrphans` (up to16 IDs), `inspectionNonces` for only the assigned known jobs, and `inspectOverflow`. `acknowledged` identifies accepted reports, `discarded` identifies receipts absent from the catalog. An `orphanInventoryComplete:true` response from the host can clear an overflow latch only under an outstanding owner inspection after checking local process/lock/receipt state. Inspection never restarts the original source and may remove only positively owned temporary copies. It does not claim the original action succeeded when its result cannot be verified.

POST `/api/nodes/{nodeId}/orphans/reconcile` requests a complete host inventory when `node.orphanOverflow` is true. The host must be connected. Repeating the request preserves the pending inspection; it never clears the latch directly. `overflowInspectionRequested` distinguishes a pending scan. This action remains available even if every retained discrepancy is already terminal.
