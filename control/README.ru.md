# Управление RolyPolyOps

[English](README.md)

## 1 Доступные функции

Панель управляет пакетом восстановления PostgreSQL/Compose из репозитория: подключает серверы, показывает наблюдаемое состояние и точки восстановления, создает зашифрованную копию, проверяет хранилище, испытывает выбранную копию, сохраняет отдельную пробную площадку и удаляет ее, применяет расписание копирования. Мастер настройки завершается только после успешной копии и проверки восстановления именно этой копии. Интерфейс доступен на русском и английском.

Обнаружение произвольных приложений, другие базы, автоматическое переключение DNS и внешнее отключение площадки не реализованы. Подключение неподдерживаемого сервера показывает это состояние и не объявляет его приложения защищенными.

## 2 Установка

Нужны Python 3.11 или новее и Linux с systemd. Сторонних зависимостей Python у службы управления нет. Получите доверенную версию исходников, закрепите ее коммит и сверьте опубликованную SHA-256 архива перед запуском с правами root. Приведенные команды доверяют локальной копии исходников.

```sh
sudo python3 control/install.py controller --origin https://control.example.org --configure-proxy
```

Установщик создает отдельного непривилегированного пользователя, постоянный каталог состояния, начальный пароль и службу systemd. Она слушает только `127.0.0.1:8090`. Параметр `--configure-proxy` добавляет маршрут только при наличии управляемого импорта Caddy `/etc/caddy/rolypolyops-routes/*.caddy`. В остальных случаях существующая конфигурация сохраняется, а подключение прокси нужно указать явно:

```caddy
handle /ops/* {
    reverse_proxy 127.0.0.1:8090 {
        header_up X-RPO-Client-IP {remote_host}
    }
}
```

Откройте `https://control.example.org/ops/`. Начальный пароль администратора находится в `/var/lib/rolypolyops-control/admin-password` и доступен через административный доступ к серверу. При первом входе измените его, затем сохраните новый пароль в своем закрытом комплекте восстановления. Открытой регистрации администратора нет. Повторная установка сохраняет каталог и учетные данные.

## 3 Подключение серверов

Нажмите «Добавить сервер» в мастере, задайте название и роль. Основная площадка может создавать копии и менять интервал; резервные площадки могут проверять и восстанавливать. Выполните показанную команду подключения из такой же доверенной копии исходников на нужном сервере. Она установит серверную службу с исходящими подключениями. Код действует 15 минут и используется один раз. Он содержит временные полномочия, поэтому его нельзя публиковать.

Серверу нужны настроенный [поддерживаемый пакет восстановления](../demo/README.ru.md), Docker/Compose, restic и закрытая конфигурация доступа к хранилищу. Эта версия распознает данный пакет; настройка неизвестных приложений и скрытая замена существующих размещений не выполняются. На предоставленном двухсерверном стенде необходимые компоненты уже настроены.

Серверные службы используют исходящий HTTPS с проверкой сертификата. Открывать им отдельный порт, загружать закрытые ключи SSH и предоставлять панели доступ к сокету Docker не требуется. Токены хранятся на сервере в закрытой конфигурации; каталог содержит их хеши. Повторное подключение меняет токен. Отзыв доступа доступен после разрешения активных операций.

## 4 Повседневная работа

Выберите сервис и точку восстановления, ознакомьтесь с планом действия и подтвердите его. Панель сохраняет операцию до отправки серверу. Повторная отправка возвращает то же задание. Страницу можно оставить открытой или перезагрузить; результат и история сохранятся. Копирование может кратковременно приостановить процесс записи демо, о чем сообщает подтверждение.

Проверка восстановления использует новые каталоги, отдельный проект и закрытые изолированные сети без публикации портов. Сохраняемая пробная копия имеет те же ограничения и не заменяет работающий сайт. Проверка HTTP выполняется внутри контейнера. Удалить можно только копию, которую учитывает серверная служба. Проверяются значения записей, хеш файла, HTTP, версия, образы, новые подключения каталогов и ограничения запуска.

Интервал копирования меняется через операцию на сервере, а не только сохранением предпочтения. Мастер сверяет наблюдаемое состояние таймера перед завершением настройки. Неизвестные и устаревшие наблюдения показываются явно. Недоступность панели не останавливает существующие местные расписания systemd.

## 5 Прерванные операции и восстановление

Состояние управления и очередь сохраняются в SQLite. Сервер записывает сведения о принятом задании до изменения системы и не повторяет прерванное действие вслепую. Действие сверки результата просит назначенный сервер проверить свою запись и подтверждение выполнения конкретной операции. Если результат установить нельзя, он остается неизвестным, а конфликтующие изменения блокируются до расследования.

Каталог содержит закрытые эксплуатационные данные. Храните копию `/var/lib/rolypolyops-control` вне сервера; для базы используйте механизм резервного копирования SQLite. Отдельно сохраняйте ключи шифрования и конфигурации серверов. Восстановленный каталог сам по себе не дает права повторно включить прежнюю основную площадку. При замене управления нужно исключить прежние полномочия и обновить регистрацию серверов.

Для отката удалите добавленный маршрут Caddy и остановите только службы `rolypolyops-control.service` и `rolypolyops-agent.service`. Существующие таймеры резервирования и проверки остаются независимыми. Удалять каталоги данных для отката панели не нужно.

## 6 Проверки и ограничения

```sh
python3 -m unittest control.test_controller control.test_agent control.test_restore_policy control.test_install
```

Эти проверки охватывают вход, защиту запросов, идентичность операций, сохранение очереди и полномочия серверной службы. Они дополняют испытания в браузере и на двух реальных серверах. Проверки не доказывают восстановление при отказе хостера, защиту от двух одновременно записывающих площадок и поддержку других пакетов сервисов. Открытое демо остается доступным только для чтения.
