# Управление RolyPolyOps

[English](README.md)

**Предварительная версия 0.2:** мастер подключает совместимый сервис Compose и репозиторий REST/S3, создает зашифрованную копию и восстанавливает ее на другом сервере. Оба варианта хранилища проверены на двух серверах Linux amd64. Границы поддержки и порядок работы: [руководство](../docs/ru/compose-services.md). Тестовое приложение сохранено.

## 1 Доступные функции

Панель управляет пакетом восстановления PostgreSQL/Compose из репозитория: подключает серверы, показывает наблюдаемое состояние и точки восстановления, создает зашифрованную копию, проверяет хранилище, испытывает выбранную копию, сохраняет отдельную пробную площадку и удаляет ее, применяет расписание копирования. Мастер настройки завершается только после успешной копии и проверки восстановления именно этой копии. Интерфейс доступен на русском и английском.

Раздел своих сервисов обнаруживает поддерживаемые обычные проекты Compose. Произвольная правильность данных других баз, автоматическое переключение DNS и внешнее отключение площадки не заявляются. Подключение неподдерживаемого сервера показывает это состояние и не объявляет его приложения защищенными.

## 2 Установка

Нужны Python 3.11 или новее и Linux с systemd. Сторонних зависимостей Python у службы управления нет. Получите полный доверенный репозиторий версии и полный идентификатор коммита у поставщика версии. Для загруженного архива сверьте предоставленную контрольную сумму. Сохраните в дереве версии `control/web`, `demo/compose.yaml` и `demo/ops`: установщик копирует помощники совместимости и при работе без тестового приложения.

Подготовьте отдельный каталог версии с владельцем root на сервере управления и на каждом сервере приложения. Выполните команды в Bash из доверенного репозитория, заменив `RELEASE_SHA` полным доверенным идентификатором коммита. Каталог назначения должен быть новым. Сам запуск через `sudo` не меняет владельца исходников в пользовательском каталоге.

```bash
set -euo pipefail
RELEASE_SHA='REPLACE_WITH_TRUSTED_FULL_COMMIT_ID'
test "$(git rev-parse --verify "$RELEASE_SHA^{commit}")" = "$RELEASE_SHA"
sudo mkdir -m 0755 "/opt/rolypolyops-release-$RELEASE_SHA"
git archive --format=tar "$RELEASE_SHA" | sudo tar -xf - --no-same-owner -C "/opt/rolypolyops-release-$RELEASE_SHA"
sudo chown -R root:root "/opt/rolypolyops-release-$RELEASE_SHA"
sudo chmod -R go-w "/opt/rolypolyops-release-$RELEASE_SHA"
cd "/opt/rolypolyops-release-$RELEASE_SHA"
```

Для повторной установки используйте сохраненный неизмененный каталог версии с владельцем root, не создавая его заново.

Выберите имя HTTPS для панели, настройте DNS, сертификат и обратный прокси. Установите управление из подготовленного каталога:

```sh
sudo python3 control/install.py controller --origin https://control.example.org
```

Установщик создает отдельного непривилегированного пользователя, постоянный каталог состояния, начальный пароль и службу systemd. Она слушает только `127.0.0.1:8090`. Публичный прокси HTTPS и запись DNS установщик не создает. Для Caddy поместите этот обработчик внутрь блока сайта TLS с именем панели, проверьте конфигурацию, затем перечитайте ее в Caddy:

```caddy
handle /ops/* {
    reverse_proxy 127.0.0.1:8090 {
        header_up X-RPO-Client-IP {remote_host}
    }
}
```

Дополнительный параметр `--configure-proxy` используйте только при наличии в Caddy управляемого импорта `/etc/caddy/rolypolyops-routes/*.caddy`. Без этого импорта установка с данным параметром останавливается, сохраняя существующую конфигурацию прокси.

Откройте `https://control.example.org/ops/` и проверьте сертификат из браузера и с обоих серверов. Начальный пароль администратора находится в `/var/lib/rolypolyops-control/admin-password` и доступен через административный доступ к серверу. При первом входе измените его и сохраните отдельно в менеджере паролей. Скачиваемый комплект восстановления репозитория не содержит пароль администратора или каталог управления. Открытой регистрации администратора нет. Повторная установка сохраняет каталог и учетные данные.

### Обновление существующей установки

При повторной установке для того же управления серверная служба может сохранить регистрацию без нового кода подключения. Сохраните ее конфигурацию, токен, идентификатор узла и весь каталог состояния. Для обновления программы не используйте замену регистрации.

Установщик заменяет файлы программы, помощники совместимости и определения служб, а также может установить недостающие зависимости. Единой транзакции обновления нет. Сначала разрешите активные операции и неизвестные результаты. Сохраните закрытый комплект восстановления: прежнюю версию и определения служб, конфигурации и состояние серверов, согласованную резервную копию SQLite-каталога управления. Первый запуск нового управления может расширить схему базы. Автоматического возврата к старой версии нет. Используйте порядок обновления и восстановления для конкретной версии, особенно если существующие службы или помощники тестового приложения должны остаться неизменными.

## 3 Подключение серверов

Откройте **Серверы**, нажмите **Добавить сервер**, задайте название первого сервера и основную роль. Выполните показанную команду из его каталога версии с владельцем root. Повторите подключение на другом сервере с ролью восстановления. Эти роли управляют тестовым приложением; для своих сервисов Compose источник и сервер восстановления выбираются отдельно у каждого сервиса. Команда устанавливает серверную службу с исходящими подключениями. Код действует 15 минут и используется один раз. Он содержит временные полномочия, поэтому его нельзя публиковать. Если код истек во время установки зависимостей, создайте новый и повторите команду.

На Ubuntu/Debian установщик серверной службы может установить недостающие Docker/Compose, restic и зависимости Python, загрузить закрепленный образ помощника. Новая установка Docker использует официальный репозиторий пакетов Docker. Библиотеки Python могут размещаться в отдельной среде исполнения. Установленный Docker не перезапускается и не обновляется; версии ниже требуемого минимума останавливают установку. systemd 252+, cgroup v2 и системный Python 3.11+ должны уже присутствовать. В других системах Linux совместимые зависимости готовят заранее. Разрешите загрузку нужных пакетов и образа, исходящий HTTPS к управлению и хранилищу. Для своих сервисов Compose настроенное тестовое приложение и `lab.env` не нужны.

Для хранилищ своих сервисов Compose нужны systemd 252+, cgroup v2 и системный Python 3.11+: операции выполняет отдельный непривилегированный процесс. Установщик создает его закрытую учетную запись, сохраняет идентификаторы в файле root0600 и проводит ограниченную проверку без ключей хранилища до использования кода подключения и замены программы. Основная служба сохраняет права для Docker и исходящей связи с панелью. Без проверенной изоляции сервер не готов к операциям хранилища.

Для сохраненного режима демо серверу нужны настроенный [поддерживаемый пакет восстановления](../demo/README.ru.md), Docker/Compose, restic и закрытая конфигурация доступа к хранилищу. Свои сервисы Compose подключайте по [руководству сервиса](../docs/ru/compose-services.md).

Серверные службы используют исходящий HTTPS с проверкой сертификата. Открывать им отдельный порт, загружать закрытые ключи SSH и предоставлять панели доступ к сокету Docker не требуется. Токены хранятся на сервере в закрытой конфигурации; каталог содержит их хеши. Повторное подключение меняет токен. Отзыв доступа доступен после разрешения активных операций.

Управляющие переменные `COMPOSE_*` и `DOCKER_*` в сохраненном окружении отклоняются до изменения файлов или загрузки образов. Для принятого пакета создается окружение с фиксированным набором параметров.

## 4 Повседневная работа

Выберите сервис и точку восстановления, ознакомьтесь с планом действия и подтвердите его. Панель сохраняет операцию до отправки серверу. Повторная отправка возвращает то же задание. Страницу можно оставить открытой или перезагрузить; результат и история сохранятся. Копирование может кратковременно приостановить процесс записи демо, о чем сообщает подтверждение.

Проверка восстановления использует новые каталоги, отдельный проект и закрытые изолированные сети без публикации портов. Сохраняемая пробная копия имеет те же ограничения и не заменяет работающий сайт. Проверка HTTP выполняется внутри контейнера. Удалить можно только копию, которую учитывает серверная служба. Проверяются значения записей, хеш файла, HTTP, версия, образы, новые подключения каталогов и ограничения запуска.

Интервал копирования меняется через операцию на сервере, а не только сохранением предпочтения. Мастер сверяет наблюдаемое состояние таймера перед завершением настройки. Неизвестные и устаревшие наблюдения показываются явно. Недоступность панели не останавливает существующие местные расписания systemd.

## 5 Прерванные операции и восстановление

Состояние управления и очередь сохраняются в SQLite. Сервер записывает сведения о принятом задании до изменения системы и не повторяет прерванное действие вслепую. Действие сверки результата просит назначенный сервер проверить свою запись и подтверждение выполнения конкретной операции. Если результат установить нельзя, он остается неизвестным, а конфликтующие изменения блокируются до расследования.

Каталог содержит закрытые эксплуатационные данные. Храните копию `/var/lib/rolypolyops-control` вне сервера; для базы используйте механизм резервного копирования SQLite. Отдельно сохраняйте ключи шифрования и конфигурации серверов. Восстановленный каталог сам по себе не дает права повторно включить прежнюю основную площадку. При замене управления нужно исключить прежние полномочия и обновить регистрацию серверов.

Управление работает в одном активном экземпляре, автоматической замены при отказе нет. Действующие таймеры на серверах могут продолжать работу без панели; новые действия мастера и управляемый перенос требуют доступного управления.

Удаление маршрута панели или остановка ее служб отключает управление, но не отменяет перенос приложения или обновление программы. Действующие расписания серверов могут продолжать работу независимо. Перед остановкой серверной службы разрешите активные операции и неизвестные результаты. Сохраните конфигурацию и каталоги состояния. Для возврата к старой программе нужен согласованный план восстановления версии и состояния. Он не разрешает запуск прежнего источника после появления новых записей на целевом сервере.

## 6 Проверки и ограничения

```sh
python3 -m unittest control.test_controller control.test_agent control.test_restore_policy control.test_install
```

Эти проверки охватывают вход, защиту запросов, идентичность операций, сохранение очереди и полномочия серверной службы. Они дополняют испытания в браузере и на двух реальных серверах. Проверки не доказывают восстановление при отказе хостера, защиту от двух одновременно записывающих площадок и поддержку других пакетов сервисов. Открытое демо остается доступным только для чтения.
