# API управления v1

[English](API.md)

## 1 Доступ

Базовый путь `/ops`, формат JSON, тело до 256 КиБ. Все закрытые данные требуют входа. Открытой регистрации администратора нет. Начальный пароль создается в закрытом файле на сервере; при первом входе нужна его смена.

Cookie сеанса имеет HttpOnly, Secure, SameSite=Strict. Для изменений нужны точный Origin и `X-CSRF-Token` данного сеанса. В каталоге хранятся хеши токенов; пароли проверяются через scrypt. Смена пароля отзывает прежние сеансы.

## 2 Адреса владельца

| Метод и путь | Назначение |
|---|---|
| GET `/api/session` | Состояние входа, версия, необходимость настройки; CSRF после входа |
| POST `/api/login` | Вход: `{password}` |
| POST `/api/password` | Смена: `{currentPassword,newPassword}` |
| POST `/api/logout` | Выход |
| GET `/api/overview` | Серверы, наблюдения, копии, задания и настройки |
| POST `/api/enrollments` | Код подключения: `{name,role}` |
| POST `/api/enrollments/{id}/cancel` | Отмена неиспользованного кода |
| POST `/api/nodes/{id}/enrollment` | Повторное подключение и замена токена |
| POST `/api/nodes/{id}/revoke` | Отзыв доступа после разрешения активных операций |
| POST `/api/settings` | `{profile,backupInterval,expectedRevision}` |
| POST `/api/plans` | `{nodeId,action,snapshotId?,parameters?}` |
| POST `/api/jobs` | `{planId,idempotencyKey}` |
| GET `/api/jobs/{id}` | Сохраненное состояние задания |
| POST `/api/jobs/{id}/cancel` | Отмена до отправки серверу |
| POST `/api/jobs/{id}/reconcile` | Сверка неизвестного результата без повторного изменения |
| POST `/api/setup/complete` | Завершение после проверенного копирования, расписания и восстановления |

Роли: `primary`, `recovery`. Профили: `single`, `pair_assisted`. Интервалы: `15min`, `hourly`, `daily`. Номер ревизии меняется при изменении конфигурации и регистрации, но не при наблюдении. Автоматическое переключение недоступно.

## 3 Операции

Действия: `backup`, `verify`, `restore-check`, `restore-preview`, `remove-preview`, `set-schedule`. Расписание принимает `{interval}` только для основной площадки. Удаление принимает `{previewId}` и относится только к учтенной пробной копии. Восстановление требует существующую точку с полным идентификатором из 64 шестнадцатеричных символов.

План связан с сервером, действием, точкой, параметрами и ревизией, действует 10 минут. Ключ повторяемости задания является UUID. Повтор возвращает прежнее задание; конфликтующее использование ключа отклоняется. Перед отправкой проверяется актуальность плана и состояния сервера. Операции сервиса выполняются последовательно.

Состояния: `queued`, `dispatched`, `running`, `succeeded`, `failed`, `outcome_unknown`. Успех восстановления требует совпадения выбранной точки и подтверждений `database-values`, `file-sha256`, `application-http`, `app-version`, `image-ids`, `fresh-mounts`, `runtime-restrictions`.

Мастер проверяет свежую успешную копию, восстановление именно этой точки на нужной цели и фактически примененное расписание. Соединение устаревает через 45 секунд, наблюдение состояния через 120 секунд. Старая успешная запись не является текущей проверкой.

## 4 Серверная служба

POST `/agent/enroll` принимает `{code,hostname,version}` и возвращает `{nodeId,token,role}`. Код используется один раз и действует 15 минут. Токен хранится на сервере в закрытом файле.

POST `/agent/sync` использует `Authorization: Bearer ...`, тело `{nodeId,status,reports}` и возвращает подтвержденные идентификаторы и необязательное задание `{id,nonce,action,snapshotId,parameters,reconcile?}`. Отчет принимается только от назначенного сервера с секретным номером данного задания. Сведения о принятии записываются до выполнения и сохраняются после подтверждения. Повторная доставка не разрешает повторное изменение.

После прерывания проверяются сохраненная запись и подтверждение конкретной операции. Неустановленный результат остается неизвестным и блокирует конфликтующие действия. Рабочие соединения используют HTTPS с проверкой сертификата. Переадресации с токеном не выполняются.

## 5 Ограничения

Службы передают состояние, свободное место, идентификаторы копий, расписания и итоги проверок. Пароли хранилища, ключи шифрования, закрытые ключи SSH, данные приложения и архивы через панель не передаются. Серверы уже должны иметь доступ к одному настроенному хранилищу.

Ошибки имеют вид `{error:"stable_code"}` без секретов и трассировки. Версия поддерживает только пакет демо. Произвольная командная оболочка, удаление истории, автоматическое переключение DNS и настройка неизвестных приложений отсутствуют.
