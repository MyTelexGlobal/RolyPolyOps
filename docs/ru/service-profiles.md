# Справочник профилей сервиса

[English](../en/service-profiles.md)

## 1 Формат

Исходный контракт: [service-package.schema.json](../../schemas/service-package.schema.json), JSON Schema Draft 2020-12. Примеры: [один сервер](../../examples/service-single.json), [пара с подтверждением](../../examples/service-pair.json) и [кластер](../../examples/service-cluster.json).

Все примеры имеют признак illustrative_only и адреса .invalid. Схема проверяет объявленную структуру и политику профиля. Она не подключается к серверу и не доказывает работу отключения, снимков, большинства или восстановления.

## 2 Поля

| Поле | Значение |
|---|---|
| format_version | Версия контракта манифеста |
| service_id | Постоянный идентификатор сервиса |
| package | Идентификатор и версия пакета поддержки |
| profile | single, pair_assisted, pair_automatic или cluster |
| nodes | Идентификаторы серверов, области отказа и объявленные роли |
| database | Движок, репликация и политика строгой синхронизации |
| failover | Автоматика, тип полномочий и обязательность блокировки источника |
| backup | Хранилища, число обязательных копий, интервал точек и история |
| targets | Требуемые RPO и RTO, а не измеренные результаты |
| restore | Изолированная цель по умолчанию и проверка приложения |
| secret_references | Идентификаторы отдельно хранимых секретов |

Паролей, токенов и закрытых ключей в манифесте быть не должно.

## 3 Ограничения профилей

single требует один узел, отсутствие репликации базы и автоматического переключения, полномочия оператора. pair_assisted требует два узла, асинхронную или синхронную репликацию, отсутствие автоматики и полномочия оператора. pair_automatic требует два узла, автоматику, полномочия provider-fence и ссылку на проверенную политику отключения.

cluster требует не менее трех объявленных узлов базы, автоматическое переключение, полномочия patroni-etcd, синхронную репликацию и строгую синхронизацию. Для всех профилей обязательны блокировка источника перед заменой полномочий и изолированное восстановление с проверкой приложения.

## 4 Проверки за пределами схемы

Схема не устанавливает реальную независимость площадок, измеренное отставание, устойчивость отключения у хостера, доступность образов, ключей и места. Уникальность идентификаторов, независимость хранилищ, соответствие обязательного числа копий доступным целям и состав etcd требуют смысловой проверки перед включением. Соответствие схеме не разрешает операцию.
