# Предварительная версия 0.2

[English](../en/release-0.2.md)

RolyPolyOps позволяет подключить существующее совместимое приложение Docker Compose через панель. Тестовое приложение сохранено.

## Что работает

- Выбор обнаруженного проекта, основного сервера и отдельного сервера восстановления.
- Подключение репозитория по HTTPS через REST или S3. Браузер шифрует учетные данные для выбранных серверов. Комплект восстановления скачивается для отдельного безопасного хранения.
- Сохранение данных приложения, переменных окружения, файлов настроек и секретов, точных образов контейнеров. Контейнеры проекта приостанавливаются на время подготовки данных, затем запускаются до отправки копии в хранилище.
- Восстановление выбранной точки в отдельную изолированную копию, проверка приложения без публикации портов.
- Включение настоящего расписания резервного копирования для сервиса, просмотр точек и результатов операций.
- Перенос проверенной копии с подтверждением оператора при доступном исходном сервере. Возможная потеря изменений определяется временем выбранной копии. Перенос последних изменений перед переключением не выполняется.

## Проверка и границы поддержки

Пути мастера для REST и S3 проверены на двух серверах Linux amd64 с Docker 29. В обоих случаях выполнены подключение репозитория к двум серверам, регистрация сервиса, копирование, изолированное восстановление, проверка HTTP и включение почасового расписания. Независимо сопоставлены контрольные записи, хеши файлов, переменных и секретов, числовые владельцы и права, конфигурации и платформы образов, изоляция восстановленной сети.

Условия установки и допустимые настройки приведены в [руководстве](compose-services.md). Требуются один работающий контейнер на каждый включенный сервис, локальные образы подходящей архитектуры и один выбранный репозиторий на сервис. Явное поле сервиса `platform` пока отклоняется. Эти испытания не подтверждают поддержку любого приложения, провайдера, процессорной архитектуры или операционной системы.

## Текущие ограничения

Панель использует один контроллер. Автоматическое переключение, отключение через провайдера, управление DNS, репликация хранилища и кластерные профили не реализованы. Перенос с подтверждением требует доступного источника и принятия потери изменений после выбранной копии.

Состояние серверных служб и каталог контроллера нужно защищать отдельно. Комплект восстановления репозитория не содержит пароль администратора или каталог. Два подключенных сервера используют один репозиторий, независимая вторая копия при этом не появляется. Очистка старых копий и настройка защиты объектов от удаления не автоматизированы. Следуйте [руководству безопасности](security.md) и проверьте восстановление данных своего приложения перед использованием.
